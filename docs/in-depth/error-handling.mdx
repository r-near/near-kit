`near-kit` converts cryptic RPC JSON errors into typed JavaScript Error classes. You can `catch` these errors and handle them logically.

## The Error Hierarchy

All errors extend `NearError`. You can check for specific types using `instanceof`.

```typescript
import {
  FunctionCallError,
  AccountDoesNotExistError,
  NetworkError,
} from "near-kit"

try {
  await near.call("contract.near", "method", {})
} catch (e) {
  if (e instanceof FunctionCallError) {
    // The contract logic failed
    console.log("Panic:", e.panic)
    console.log("Logs:", e.logs)
  } else if (e instanceof AccountDoesNotExistError) {
    // The account isn't real
    console.log(`Account ${e.accountId} not found`)
  } else if (e instanceof NetworkError) {
    // RPC is down
    if (e.retryable) {
      // You might want to try again
    }
  }
}
```

## Error Types

<AccordionGroup>
  <Accordion title="FunctionCallError" icon="code">
    Thrown when a smart contract call fails (panics or runs out of gas).
    
    **Properties:**
    - `panic`: The panic message from the contract
    - `logs`: Any logs emitted before the failure
    
    ```typescript
    if (e instanceof FunctionCallError) {
      console.log("Contract panicked:", e.panic)
    }
    ```
  </Accordion>
  
  <Accordion title="AccountDoesNotExistError" icon="user-slash">
    Thrown when trying to interact with an account that doesn't exist.
    
    **Properties:**
    - `accountId`: The account that wasn't found
    
    ```typescript
    if (e instanceof AccountDoesNotExistError) {
      console.log(`Account ${e.accountId} not found`)
    }
    ```
  </Accordion>
  
  <Accordion title="NetworkError" icon="wifi-slash">
    Thrown when there's a network or RPC issue.
    
    **Properties:**
    - `retryable`: Whether it's safe to retry
    - `statusCode`: HTTP status code (if applicable)
    
    ```typescript
    if (e instanceof NetworkError && e.retryable) {
      // Wait and try again
    }
    ```
  </Accordion>
  
  <Accordion title="InsufficientBalanceError" icon="wallet">
    Thrown when an account doesn't have enough NEAR for the operation.
    
    **Properties:**
    - `accountId`: The account with insufficient balance
    - `required`: Amount needed
    - `available`: Amount available
  </Accordion>
  
  <Accordion title="InvalidNonceError" icon="rotate">
    Thrown when a transaction's nonce is stale (usually from concurrent transactions).
    
    <Tip>
    Use `RotatingKeyStore` to avoid nonce issues in high-concurrency scenarios.
    </Tip>
  </Accordion>

  <Accordion title="TransferToUniversalAccountNotAllowedError" icon="ban">
    Thrown when a transaction, or a receipt created by a contract, transfers NEAR to a universal account (a `0u...` id) while the network bans such transfers. nearcore rejects them until universal accounts are enabled, so retrying won't help before then.

    **Properties:**
    - `accountId`: The universal account the transfer targeted
    - `retryable`: Always `false`

    ```typescript
    if (e instanceof TransferToUniversalAccountNotAllowedError) {
      console.log(`Can't send to ${e.accountId} yet`)
    }
    ```
  </Accordion>

  <Accordion title="ExternalCallRefusedError" icon="hand">
    Thrown when a contract refuses an external call, from a dry run (`viewExternalCall()`) or from a copy refused when it ran.

    **Properties:**
    - `contractId`: The contract that refused it
    - `error`: The reason, as nearcore's `TxExecutionError` (`ContractNotFound` when the account has no contract)
    - `logs`: The logs of the contract's run
    - `retryable`: `true` only when the chunk's share for external calls was used up
  </Accordion>

  <Accordion title="ExternalCallTimeoutError" icon="clock">
    Thrown when `externalCall()` times out before the node finds a copy of the call. A refused call is dropped, so it ends this way too. The call may still land: see [finding a copy](/in-depth/external-calls#timeouts-and-finding-a-copy).

    **Properties:**
    - `callHash`: The hash every copy's unique id comes from
    - `sentAtHeight`: The head height seen before sending
  </Accordion>

  <Accordion title="ReservedMethodNameError" icon="lock">
    Thrown when a signed transaction's `FunctionCall` calls `__external_call`. Only an external call or a view call can run that method.
  </Accordion>

  <Accordion title="UnknownTransactionError" icon="magnifying-glass">
    Thrown when the node doesn't know the transaction hash or external call unique id asked for. It may not have landed yet.

    **Properties:**
    - `transactionHash`: The hash or unique id asked for
  </Accordion>

  <Accordion title="UninitializedAccountError" icon="user-clock">
    Thrown when a view targets a funded universal account whose state init isn't installed yet (nearcore 2.15). Pass the state init in the view's `stateInit` option to run it anyway.
  </Accordion>
</AccordionGroup>

## Panic Messages

When a contract fails, the most important info is the **Panic Message**. `near-kit` extracts this from the deep RPC response and puts it right on `error.panic`.

Common panics include:

- `ERR_NOT_ENOUGH_FUNDS`
- `ERR_INVALID_ARGUMENT`
- `Smart contract panicked: ...`

Use this string to debug or show user-friendly error messages in your UI.
