# Test ownership after simplification

Comparison: `95111ba2076939ae8ab9820bd27428214858e245` to source candidate
`1d314715725520178a9c659ee6bb6ef5832a8589`.

The goal is fewer implementation constraints and stronger behavioral proof, not a
test-deletion target. No test file was deleted. The local core/wallet total changes
from 1,329 to 1,316; React changes from 52 to 54. The 25 real-chain integration
files remain. Exact final CI and independent gate results belong in the separate
acceptance report.

The [literal declaration inventory](test-change-inventory.json) records exact old
and new test titles, file paths, and source line numbers. It is not a runtime test
count: renames and consolidation into `test.each` appear as removed/added titles,
and a table declaration expands into multiple actual cases. Reproduce it from the
repository root:

```sh
node docs/experiments/simplification/test-change-inventory.mjs \
  95111ba2076939ae8ab9820bd27428214858e245 \
  1d314715725520178a9c659ee6bb6ef5832a8589
```

In particular, the RPC classifier's “should throw” to “returns” renames preserve
its error cases.

## Safeguards deliberately retained

- Nonce generation/invalidation and keyed locking protect stale-read and concurrent
  reservation races. A TTL cache or naive Ref replacement would lose this proof.
- Sandbox stop-before-restart, uninterruptible close transition, scoped fibers,
  real fixture processes and finalizers enforce actual resource ownership.
- Fixed transaction/delegate hashes, Borsh vectors and cryptographic verification
  are independent commitments; expected bytes are not generated by the encoder
  under test.
- Rejection identity, malformed numeric/base64/JSON data, gas-key snapshots,
  cancellation and wallet approval counts remain negative regressions.
- Native error/environment inference is checked by compile-only fixtures in the
  real CI typecheck, rather than relying on transpiled `expectTypeOf` calls.
- Real-chain integration, minimum Node behavior, React 18 compatibility, browser
  bundles and package exports remain separate gates. Passing unit tests does not
  substitute for them.

## Change and verification accounting

Production source changed by +2,804/-5,334 physical lines (net -2,530); tests,
test support and compile-only consumers changed by +1,715/-1,930 (net -215).
This includes formatting and types; the separate architecture inventory strips
comments and blank lines as a second measure. No percentage is a quality score.

Every lane ran focused owner tests before integration. The clean source candidate
passed `bun run check`, all 1,316 core/wallet tests, and all 54 React tests locally.
Independent review reproduced and repaired the transaction-overload ambiguity,
malformed nested RPC error defect and pre-broadcast InvalidNonce retry; the React
authority regression was independently demonstrated before its repair. Final
isolated install, cross-runtime checks, differential corpora, package/browser
proof, benchmarks and exact-source CI are recorded in the acceptance report.
